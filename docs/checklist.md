## Как пользоваться

Чек-лист устроен как пять блоков вопросов и план на квартал. Проходите по порядку: блоки 1–3 показывают, готова ли компания, блок 4 задаёт первый шаг, блок 5 — то, чем вы будете отчитываться.

Отвечайте честно. Каждое «нет» — это не повод не начинать, а конкретная работа, которую придётся сделать до, а не после.

## Блок 1. Готовность инженерного контура

Без этого переход даёт не ускорение, а те же проблемы на большей скорости.

- [ ] Существует автоматика, которая **останавливает выпуск**, когда что-то сломалось, а не просто рисует отчёт
      *Проверка: когда автотесты последний раз остановили выкатку? «Никогда» или «отключаем, когда горит срок» = нет*
- [ ] Автопроверки проходят без ручной подготовки тестовых данных
- [ ] Известно время от постановки задачи до прода — измеряется, а не оценивается на глаз
      *Проверка: назовите цифру для типовой задачи прошлого месяца*
- [ ] Релизное окно не длиннее двух недель (иначе выигрыш в разработке не дойдёт до бизнеса)
- [ ] Систему можно быстро вернуть в рабочее состояние после неудачного релиза
      *Проверка: когда откат последний раз выполняли или репетировали? Больше 3 месяцев назад = нет*
- [ ] Есть наблюдаемость в проде: метрики, логи, трассировка, алерты
- [ ] Код разделён на модули с внятными границами хотя бы в той части, где планируется первый заход

**Меньше 4 галочек** → начинать с автотестов и релизного цикла, а не с агентов.

---

## Блок 2. Готовность контура контроля

Это то, о чём спросит безопасность, аудит и регулятор. Лучше ответить себе до того, как спросят.

- [ ] Понятно, какие данные попадают в контекст агента и в логи
- [ ] Персональные данные маскируются, в том числе в отладочных логах и тестовых выборках
- [ ] Есть решение, где размещается модель и допустима ли она для вашего контура
- [ ] По любому изменению можно восстановить, зачем его сделали и кто одобрил
      *Проверка: возьмите изменение прошлой недели и ответьте на оба вопроса за 10 минут*
- [ ] Требования безопасности можно превратить в автоматические проверки, а не в согласование в конце
- [ ] Определено, какие действия агент **не может** совершать ни при каких условиях
- [ ] Согласовано, кто утверждает план перед исполнением и по какому признаку

**Совет:** заходите к безопасности с предложением автоматизировать уже принятые требования. Не с просьбой об исключении — это другой разговор и другой результат.

## Блок 3. Права агента по обратимости

Составьте таблицу для своего домена. Уровень назначается по цене ошибки, а не по тому, насколько вы довольны командой.

| Уровень | Что агент делает | Кто подтверждает | Примеры из вашего домена |
|---|---|---|---|
| Только предлагает | Черновики, идеи | Никто | |
| Готовит изменение | Код, тесты, спецификации | Человек перед мержем | |
| Исполняет по плану | Утверждённый план целиком | Человек на плане, не на каждом шаге | |
| Работает в домене | Очерченная область | Автоматическая проверка + выборочный аудит | |

- [ ] Таблица заполнена для минимум трёх типов задач
- [ ] Количество подтверждений в день посчитано и не превышает того, что человек реально прочитает
- [ ] Определено, что делать при отказе агента посреди длинной задачи

**Красный флаг:** если подтверждений больше десятка в день, их начнут давать не читая. Формальный контроль хуже отсутствующего — он создаёт ложную уверенность и портит доказательную базу.

## Блок 4. Первый заход: 30 дней

- [ ] Выбрана **одна** команда — добровольно, не распоряжением
- [ ] Выбрана **одна настоящая** задача из бэклога, не учебная и не в песочнице
- [ ] Задача среднего размера: требует требований, тестов и прохождения через безопасность
- [ ] Команде сказано прямо, планируются ли сокращения по итогам (если нет — скажите это вслух)
- [ ] Назначен человек, который ведёт записи по ходу

**Что обязательно зафиксировать по итогам — это и есть результат месяца:**

- [ ] Список контролей, которые **не сработали**
- [ ] Где команда правила план агента и почему
- [ ] Соотношение времени на проверку и на исполнение
- [ ] Стоимость прохода в деньгах
- [ ] Что в требованиях выяснилось на входе вместо третьей недели

**Не масштабировать до конца месяца.** Соблазн будет.

## Блок 5. Метрики и отчётность

Держите парами: второй показатель ограничивает первый.

| Пара | Показатель | Ограничитель |
|---|---|---|
| Скорость / качество | Время от идеи до прода | Доля релизов с откатом и дефектами |
| Автономия / доверие | Доля самостоятельных действий агента | Доля изменений, пригодных для разбора инцидента |
| Результат / стоимость | Выпущено единиц работы | Стоимость единицы результата |

- [ ] Метрики сняты **до** начала, есть база для сравнения
- [ ] В периоде вводится только одно заметное изменение (иначе вы измеряете календарь, а не причину)
- [ ] На слайде наверх скорость никогда не идёт без парного качества
- [ ] Есть ответственный за наблюдение за агентами в проде

**Не измеряйте:** объём сгенерированного кода, долю принятых подсказок, сэкономленные часы по опросу. Все три растут, когда дела идут хуже.

## План на квартал: коротко

**Месяц 1.** Одна команда, одна реальная задача, полный проход. Результат — список дыр в контроле и цена прохода.

**Месяц 2.** Закрыть найденное: автопроверки с порогами, след действий, комплект доказательств готовности на каждый кусок работы, уровни прав. Первый предметный разговор с безопасностью.

**Месяц 3.** Ещё две команды: одна на новом проекте, одна на легаси. Цель не скорость, а понимание, что переносится, а что упирается в специфику.

## Шесть способов потратить квартал впустую

1. Поставить ИИ поверх неизменного процесса
2. Сделать пилот на учебной задаче в песочнице
3. Завалить команду подтверждениями
4. Вложить бюджет в подписки вместо подготовки окружения
5. Отчитываться одной метрикой скорости
6. Перерисовать роли и структуру до первой реальной задачи

---

## Формулировка для совета директоров

> За квартал мы получаем измеренный проход на реальной задаче, список дыр в контуре контроля и стоимость единицы результата. После этого принимаем решение о масштабировании.

Просите не веру, а один квартал и одну команду под понятный результат. Формулировка «внедряем ИИ в разработку» уводит разговор в обсуждение хайпа и заканчивается ничем.
